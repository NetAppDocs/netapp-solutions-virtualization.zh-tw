= 使用 SnapMirror Active Sync（SAN 和 NAS）為 VCF 管理網域設定延伸叢集
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
在此用例中，我們概述了使用ONTAP tools for VMware vSphere為 VCF 管理域配置延伸叢集的過程。此流程包括部署 vSphere 主機和 vCenter Server、安裝ONTAP工具、使用SnapMirror Active Sync 保護資料儲存庫、將虛擬機器移轉到受保護的資料儲存庫以及配置補充儲存。

image:vmw-vcf-vmsc-mgmt-smas-001.png["使用ONTAP為 VCF 管理域延伸集群"]

SAN 支援均勻和非均勻擴展叢集組態。若為 NAS，則採用 ONTAP 9.19.1 的主動被動式組態。

[NOTE]
====
主機鄰近性設定與多重路徑組態結合使用，以確保儲存設備流量選擇最佳路徑。對於 SCSI，主機鄰近性設定在 igroup 上設定；對於 NVMe-oF，主機鄰近性設定在子系統上設定。例如，在統一主機存取組態中，主機可以存取延伸叢集中的兩個儲存系統。在多重路徑組態中，最佳路徑和非最佳路徑會根據主機鄰近性設定進行配置。

====


[[scenario-overview]]
== 場景概述

擴展叢集解決方案可以部署在預設叢集或 VCF 管理網域或工作負載網域中的附加叢集上。ONTAP tools 10.6 支援在 iSCSI 和 FC 傳輸協定的 VMFS 資料存放區上使用 SnapMirror 主動同步進行資料存放區保護。ONTAP 支援 SnapMirror 主動同步適用於 SAN（iSCSI、FC、NVMe-oF）和 NAS（NFS v3 及 NFSv4.1）。對於 SAN 傳輸協定，保護在一致性群組層級執行；對於 NAS，則在 SVM 層級執行。下圖說明使用 ONTAP tools for VMware vSphere 搭配 FC 協定之 VMFS 的 VCF 管理網域擴展叢集解決方案。

image:vmware-vcf-asa-mgmt-stretchcluster-002.png["使用ONTAP為 VCF 管理域延伸集群"]

.管理域上的主體存儲
[%collapsible%open]
====
. 使用任何受支援的傳輸協定部署 VCF 管理網域。
+
.. 對於基於 FC 和 NFSv3 的 VMFS，可以直接使用 VCF 安裝程式工具。對於 iSCSI、NVMe-oF 和 NFSv4.1，需要先設定 vCenter，然後再使用 VCF 安裝程式工具部署管理網域。如需詳細資訊，請參閱 link:vmw-vcf-migrate.html["使用 iSCSI、NVMe-oF 和 NFSv4.1 部署 VCF 管理域"]


. ONTAP tools for VMware vSphere
. 為 VMware vSphere 部署SnapCenter插件（選用）
. 保護資料儲存。
+
.. 對於 iSCSI 和 FC，需使用 ONTAP tools 10.6 或更高版本來保護資料儲存。對於 NVMe-oF 和 NFSv4.1，則需使用系統管理程式來保護資料儲存。如需參考，請查看下方 NVMe/TCP 和 NFS 的影片示範。




====
.管理域上的補充存儲
[%collapsible%open]
====
管理網域啟動並執行後，即可使用 ONTAP tools 10.6 或更高版本建立其他資料存放區，並使用 SnapMirror 作用中同步保護 iSCSI 和 FC。對於 NVMe-oF 和 NFS，請參考下方的影片示範以供參考，該示範是在工作負載網域上執行的，但相同的步驟也適用於管理網域。

====
