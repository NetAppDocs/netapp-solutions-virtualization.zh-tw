[role="lead"]
了解 VMware vSphere 虛擬 Volume（vVols）、採用它們的原因、其架構，以及 ONTAP NFS 資料存放區如何作為替代方案。ONTAP NFS 資料存放區簡化了管理並增強了擴充性，同時維持虛擬化環境所需的效能與靈活度。



[[solution-overview]]
== 解決方案概述

私有雲環境需要規模、靈活度與操作簡易性。vVols 是在 vSphere 6.0 中引進，可在個別 VM 磁碟層級套用原則，並透過使用 SCSI 儲存設備的次要 LUN 功能來解決 LUN 限制。

LUN 多路徑和 NFS 裝載由協定端點（PE）處理，作為儲存陣列的資料路徑。

在 ONTAP vVols 實作中，每個用於 SCSI LUN 的 FlexVol Volume 都有一個 PE，SVM 上用於 NFS 協定的每個邏輯介面（LIF）也都有一個 PE。

[[scale-considerations]]
=== 規模考量

由於每個 VM 磁碟都是採用 vVols 的分隔 LUN，因此環境很快就會接近每個 ESXi 主機支援的最大 LUN 和路徑數量。vVols 透過使用次要 LUN 功能來解決 LUN 規模問題，這需要儲存陣列和架構交換器的支援。

NFS 資料儲存區不受每台主機 LUN 限制。ESXi 每台主機最多支援 256 個 NFS 資料儲存區裝載。如需目前的限制，請參閱 link:https://configmax.broadcom.com["VMware 組態最大值"^]。



[[storage-consumption-models]]
=== 儲存設備消耗模型

使用 NFS 時，資料儲存區透過安裝點使用，虛擬機器組態和資料檔案儲存在 Volume 中。新增儲存設備 Volume 需要額外的安裝點。

vVols 透過新增更多 FlexVol Volume 來解決容量限制，協定端點指向每個 LIF 上的 SVM 根目錄。vVols 資料儲存區是一個儲存 Container，其容量是附加至該容器的所有 FlexVol Volume 的總容量。

vVols 包含多種物件類型：組態、資料、交換空間、Snapshot 快照技術和記憶體容量。vVols 預設採用資源隨需配置。



[[vasa-and-storage-policy-management]]
=== VASA 和儲存設備原則管理

Snapshot 快照技術、 VM 磁碟複製、複寫和其他儲存設備作業，會透過使用 vSphere 儲存感知 API （VASA）卸載至儲存陣列， VASA 是 vVols 的核心元件。

一些儲存設備廠商在陣列上實作 VASA。NetApp 在 ONTAP tools for VMware vSphere 中於陣列外實作 VASA，因此單一執行個體可以管理多個陣列。

基於儲存設備原則的管理（SPBM）會根據所需的儲存設備原則，將 VM 磁碟放置在特定的儲存設備上。



[[why-organizations-use-vvols]]
== 組織為何使用 vVols

組織因以下幾個原因而採用 vVols：

* *精細的儲存管理*：儲存原則套用於單一 VM 磁碟層級，從而精確控制效能、可用度與資料保護。
* *簡化操作*：透過 SPBM 實現儲存設備資源配置與管理的自動化，減少手冊工作與錯誤。
* *卸載儲存設備操作*：Snapshot 快照技術、複製和複寫透過 VASA 卸載到儲存陣列。
* *提升的擴充性*：協定端點和次要 LUN 克服了傳統每部主機的 LUN 限制。
* *VMware 生態系統整合*：vVols 與 VMware 工具和工作流程緊密整合，包括自動化原則執行。


由於 vVols 已被棄用，組織需要一種替代方案，既能維持這些營運優勢，又不依賴 VASA。



[[architecture-overview]]
== 架構概述

NFS 是 vSphere 環境的熱門選擇，因為它具有簡單性、擴充性和靈活度。NFS 資料存放區易於資源配置與擴充，並能以極少的管理例行成本支援大規模部署。有了 ONTAP，NFS 增加了多重路徑、用於提升效能的 nConnect，以及與 VMware 工具的整合。



[[ontap-nfs-advantages]]
=== ONTAP NFS 優勢

ONTAP 客戶重視 link:https://docs.netapp.com/us-en/ontap-apps-dbs/vmware/vmware-vsphere-datastores-nfs.html["NFS 資料存放區"^] 的簡易性，包括跨 vCenter Server 執行個體移動資料的能力。透過 ONTAP，您可以恢復單一 VM 磁碟，而不會影響同一個 Volume 上的其他 VM。

單一 ONTAP FlexGroup Volume 可垂直擴充至 20 PB 和 4,000 億個檔案，並可託管數千個虛擬機器。單一虛擬機器磁碟最大可達 62 TB。ONTAP Snapshot 快照技術複本可簡化備份與恢復作業。



[[performance-and-disaster-recovery-tools]]
=== 效能和災難恢復工具

NetApp NFS Plug-in for VMware VAAI （vSphere APIs for Array Integration） 可將複製等作業卸載至儲存陣列，以提升效能。

針對災難恢復，NetApp 提供適用於 VMware Live Site Recovery（先前稱為 VMware Site Recovery Manager）的儲存複寫介面卡（SRA），以及 link:vmw-dr-gs.html["NetApp Disaster Recovery"] 服務。

image:vmw-vvol-nfs-migration-004.png["NFS VAAI"]



[[nfs-operational-simplicity]]
=== NFS 操作簡便性

下圖比較了託管在實體伺服器（左）、NFS 資料儲存中的虛擬機器（中），以及 vVols 資料儲存中的虛擬機器（右）上的兩個應用程式。在 vVols 和 NFS 資料儲存上託管虛擬機器非常相似。

image:vmw-vvol-nfs-migration-003.png["vVols 和 NFS"]

NFS 資料儲存區的日常運作不依賴 VASA 和 SPBM。NFS 資料儲存區可以裝載到多個 vCenter Server 執行個體上，並支援 vMotion、DRS、HA、FT 和其他 VMware 功能。管理員使用 ONTAP tools for VMware vSphere 從 vSphere Client 管理儲存設備。



[[ontap-cluster-architecture]]
=== ONTAP 叢集架構

ONTAP NAS 叢集可垂直擴充至 24 個節點。每個節點可擁有多個彙總，且每個彙總可包含多個 FlexVol 或 FlexGroup Volume。SVM 可跨越節點，並可擁有多個用於 NFS 協定的 LIF。ESXi 主機可透過每個 LIF 裝載 NFS 資料存放區。



[[pnfs-support]]
=== pNFS 支援

pNFS 允許用戶端透過多個網路路徑平行存取儲存設備，進而提升效能與擴充性。ONTAP 支援搭配 NFSv4.1 的 pNFS，使 ESXi 主機能夠在 ONTAP SVM 上使用多個 LIF 進行平行資料存取。

下列映像顯示用於測試 pNFS 的範例設定。

NOTE: pNFS 需要 link:https://docs.netapp.com/us-en/ontap/nfs-admin/enable-disable-pnfs-task.html["需要在 SVM 上啟用 pNFS 選項"^]。pNFS 僅支援 NFSv4.1。



[[benefits-of-migrating-to-ontap-nfs]]
== 移轉至 ONTAP NFS 的效益

從 vVols 資料存放區移轉至 ONTAP NFS 資料存放區有以下幾個優點：

* *簡化管理*：使用 ONTAP tools for VMware vSphere（與 vCenter 整合）來資源配置、擴充及管理 NFS 資料儲存區。
* *擴充性*：FlexGroup Volume 支援單一資料存放區中的數千台虛擬機器。
* *效能*：NFS 多路徑、nConnect 與 ONTAP 最佳化交付高處理量與低延遲。
* *資料保護*：ONTAP Snapshot 快照技術複本提供快速、極具空間效率的備份與還原，而不會影響 VM 效能。
* *操作靈活度*：NFS 資料儲存可以跨多個 vCenter Server 執行個體掛載，並支援 vMotion、DRS、HA 和 FT。
* *整合*：ONTAP NFS 可與 NFS VAAI 外掛、VMware Live Site Recovery 和 NetApp Disaster Recovery 搭配使用。
* *有效率的空間使用率*：精簡配置、重複資料刪除和壓縮可降低儲存設備成本。
* *安全性與法規遵循*：匯出原則、RBAC、Kerberos 與加密可保護資料並控制存取。
* *面向未來*：NFS 不受 vVols 棄用影響，確保長期相容性與支援。
