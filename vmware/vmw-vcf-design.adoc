[cols="4,2,2"]
|===
| 產品系列 | FC 上的 VMFS | NFSv3

| AFX | 不 | 是的 


| AFF A系列和C系列 | 是的 | 是的 


| FAS | 是的 | 是的 
|===
[cols="4,2,2,2,2,2"]
|===
| 產品系列 | FC 上的 VMFS | iSCSI 上的 VMFS | NVMe-oF 上的 VMFS | NFSv3 | NFSv4.1

[[blueprints]]
== 藍圖

以下藍圖說明了 VMware Cloud Foundation 和ONTAP在各種網站和資源情境中的常見部署模式。



[[vcf-fleet-in-a-single-site-with-minimal-footprint]]
=== VCF 車隊位於單一站點，佔地面積極小

此設計方案旨在以最少的資源，在單一 vSphere 叢集中部署管理和工作負載元件。它支援 VMFS 和 NFSv3 主要資料存放區，並提供簡單的雙節點組態部署選項。

image::vmw-vcf-design-001.png[VCF 車隊位於單一站點，佔地面積極小]

為了最大限度地減少資源消耗，請盡可能使用現有的ONTAP工具實例。如果不可用，則小型設定檔的單一節點是合適的。SnapCenter Plug-in for VMware vSphere使用本機快照和複製到另一個ONTAP儲存陣列來保護虛擬機器和資料儲存區。


NOTE: 如果您缺乏資源來探索 VCF，許多雲端供應商都提供 VCF 即服務，且ONTAP可作為雲端供應商的第一方服務使用。

如需此設計的詳細資訊，請參閱link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-in-a-single-site-with-minimal-footprint-blueprint.html["Broadcom 技術文件在單一網站的 VCF Fleet 上以最小的佔用空間提供"]。



[[vcf-fleet-in-a-single-site]]
=== 單一站點內的 VCF 車隊

此設計藍圖適用於依賴應用程式高可用性的單一主資料中心的客戶。通常，它涉及單一 VCF 環境。您可以將ASA用於區塊工作負載，將AFF用於文件/統一工作負載。

內容儲存庫在 VCF 網域之間共用 VM 範本和容器註冊表。當託管在FlexGroup Volume 上時， FlexCache功能可用於訂閱資料儲存。


CAUTION: 不支援在FlexCache資料儲存上託管虛擬機器。

image::vmw-vcf-design-002.png[VCF 車隊集中於一個站點]

HA 模式下的ONTAP工具的單一實例可以管理 VCF Fleet 中的所有 vCenter。請參閱link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/deploy/prerequisites.html#configuration-limits-to-deploy-ontap-tools-for-vmware-vsphere["ONTAP工具的設定限制"]了解更多。  ONTAP工具與 VCF SSO 和 VCF OPS 智慧分組集成，可在同一 UI 中進行多 vCenter 存取。

.帶有ONTAP工具的 VCF 補充資料存儲
video::e7cf90b9-2744-404b-9831-b33f00164626[panopto]
您必須在每個 vCenter 執行個體上部署SnapCenter插件以保護虛擬機器和資料儲存區。

儲存原則型管理與 vSphere Supervisor 搭配使用，用於主機控制 VKS 的虛擬機器。標籤在 VCF Ops 中集中管理。NetApp Trident CSI 與 VKS 搭配使用，利用原生陣列功能提供應用程式備份保護。使用 vSphere CSI 時，持續儲存 Volume 詳細資料會顯示在 vCenter 以及 VCF Automation 上。

有關此藍圖的更多詳細資訊，請參閱 link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-in-a-single-site-blueprint.html["Broadcom 在單一網站上提供 VCF Fleet 技術文檔"]。



[[vcf-fleet-with-multiple-sites-in-a-single-region]]
=== 單一區域內有多個站點的 VCF 機群

此設計適用於透過將工作負載分散到不同的故障域來提供具有更高可用性的類似雲端的服務的客戶。

對於 VMFS 資料儲存庫， SnapMirror主動同步提供了主動-主動儲存單元，可與 vSphere Metro Storage Cluster 一起使用。統一存取模式提供透明的儲存故障轉移，而非統一存取模式則要求在故障域發生故障時重新啟動虛擬機器。

對於 NFS 資料存放區，適用於 NAS 的 SnapMirror 主動同步（搭配 ONTAP 9.19.1 及更高版本）或 ONTAP MetroCluster 與 vSphere Metro Storage Cluster 的整合可確保高可用度。仲裁器可避免腦裂情況，現在可託管於 NetApp Console 上。

VM 放置規則控制管理域元件的相同故障域內的 VM。

image::vmw-vcf-design-003.png[單一區域內有多個站點的 VCF 機隊]

ONTAP tools 提供了一個使用者介面，用於設定 iSCSI 和 FC 的 SnapMirror 主動同步關係。兩個故障域的儲存系統都必須在 ONTAP tools 和 SnapCenter Plug-in for VMware vSphere 中註冊。

您可以使用NetApp Backup and Recovery for VMs 透過SnapMirror和SnapMirror to Cloud 實現 3-2-1 備份策略。您可以從三個位置中的任一個執行復原。

Trident Protect 或 NetApp Console Backup and Recovery for Kubernetes 保護 VKS 叢集應用程式。

更多資訊請查看link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-with-multiple-sites-in-a-single-region-blueprint.html["Broadcom 有關單一區域內具有多個網站的 VCF 叢集的技術文檔"]。



[[vcf-fleet-with-multiple-sites-across-multiple-regions]]
=== 擁有多個區域多個站點的 VCF 車隊

此設計針對的是遍佈全球的客戶，提供就近的服務和災難復原解決方案。

您可以使用 VMware Protect and Recovery 或 NetApp Console 災難恢復來管理 VM 的災難恢復。ONTAP tools 提供 SRA（Storage Replication Adapter）來協調 ONTAP 的儲存設備作業。

[cols="4,2,2,2"]
|===
| 產品系列 | SnapMirror主動同步 | 適用於 NAS 的 SnapMirror active sync | MetroCluster 


| ASA A系列和C系列 | 是的 | 不 | 是的 


| AFX | 不 | 是的 | 不適用 


| AFF A系列和C系列 | 是的 | 是的 | 是的 


| FAS | 不 | 不 | 是的 
|===
image::vmw-vcf-design-004.png[擁有多個區域多個站點的 VCF 車隊]

ONTAP工具為資料儲存區複製設定提供了 UI。NetApp Console也可用於儲存陣列之間的複製。SnapCenter Plug-in for VMware vSphere利用現有的SnapMirror關係式來實作 SnapShot。

更多資訊請查看link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-with-multiple-sites-across-multiple-regions-blueprint.html["Broadcom 關於跨區域多站點 VCF Fleet 的技術文檔"]。



[[vcf-fleet-with-multiple-sites-in-a-single-region-plus-additional-regions]]
=== VCF 機群在單一區域和其他區域設有多個站點

該設計解決了虛擬機器和 VKS 應用程式的可用性和災難復原問題。

ASA、AFX、AFF 和 FAS 支援此設計選項。

image::vmw-vcf-design-005.png[VCF 車隊在單一區域及其他區域設有多個站點]

您可以使用ONTAP工具或NetApp Console來設定複製關係。

如需更多資訊、請參閱 link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/design/design-blueprints-for/infrastructure-modernization/vcf-fleet-with-multiple-sites-in-a-single-region-plus-additional-region-blueprint.html["Broadcom 有關在單一區域和其他區域內具有多個網站的 VCF Fleet 的技術文檔"] 。
